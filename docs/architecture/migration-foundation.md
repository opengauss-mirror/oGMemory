# 迁移协调基础

本组件只提供迁移期间的状态协调，不读取迁移数据，也不实现导出、恢复、合并或索引重建。

## 能力

- 使用工作区 SQLite 保存维护任务、业务操作和参与进程状态。
- 通过内容写入许可暂停源端持久化写入，保留读取操作。
- 在目标导入期间阻止业务操作。
- 通过参与进程确认排空、刷新和恢复阶段。
- 由服务自身提供暂停、刷新和恢复回调。

## 使用边界

后端备份与恢复、迁移包、记录合并、向量重建、数据库转换、内容存储转换、共享空间迁移和 GUI 不属于本组件。每个业务进程向 `Participant` 提供服务回调，并通过 `Participant.admission` 获取许可。

- 读取使用 `scope()`。
- 普通运行态写入使用 `scope(OperationKind.RUNTIME_WRITE)`，导出期间可继续。
- 持久化迁移内容必须使用 `content_scope()`，导出快照期间受内容写屏障约束。

## 状态流程

```text
导出：空闲 → 暂停并排空内容写入 → 固定副本 → 开放写入
导入：空闲 → 排空读写并暂停参与者 → 执行导入或恢复 → 刷新参与者 → 开放读写
```

目标执行器确认导入或恢复完成后请求刷新。导入期间启动的参与者加入当前任务。所有参与者确认刷新后才能开放目标。回调须可重试。执行器退出会释放执行锁，维护状态仍存于 SQLite，供接管进程确认并恢复。导入前调用 `wait_drained()` 确认在途操作已排空、参与者已确认暂停。确认进程已退出后，清理其遗留的纯读许可，保留未确认的写许可。服务直接向 `Participant` 提供回调，恢复回调返回 `False` 时保留待恢复状态。调用方通过 `mark_write_uncertain()` 保留结果未确认的写许可。
