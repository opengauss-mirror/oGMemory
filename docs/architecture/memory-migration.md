# 记忆迁移设计

## 目标与范围

仅实例管理员 ROOT 可迁移当前实例中已持久化的业务记忆。源端保持服务和读取可用，仅在固定快照副本期间暂停内容持久化；目标导入期间禁止业务读写，支持向已有数据合并，失败后恢复导入前状态。

迁移包沿用统一逻辑协议，包含节点正文、摘要、元数据、关系、历史归档及必要附件。向量、运行队列、锁、临时状态和凭证不进入迁移包；目标按自身配置重建索引。来源模型与存储描述仅用于兼容检查和提示，不覆盖目标配置。未支持的必要依赖明确拒绝。

## 源端导出

1. 准备临时目录和导出任务。
2. 在统一内容存储层关闭新的持久化修改许可，等已经开始的完整内容修改完成。多进程共用同一许可状态；不等待整个 HTTP／MCP 请求、模型计算或索引追平。
3. 读取并固定业务记录和附件字节。一次完整内容修改的正文、元数据和关系不能被快照截断；修改附件也必须遵守同一屏障。
4. 副本固定后立即恢复持久化写入，再从副本校验、压缩和发布下载文件。副本固定后的源端变化不记录、不补齐。

等待和复制共用一个停写预算，底层读操作和分块处理受剩余期限约束。超时、复制失败或控制权丢失时废弃副本并恢复源端写入。未确认完成的内容写入不能被强制当作结束。普通复制的停写时间随数据量增长，超过预算则本次导出失败。

索引投影、Outbox 运行状态不纳入源端停写范围；其中实际修改迁移业务内容的操作仍通过内容存储屏障。快照不触发全服务暂停、缓存刷新或向量客户端关闭。

## 目标导入与恢复

上传、格式与资源限额检查、来源差异展示先行完成。执行导入时禁止业务读写，排空目标在途操作并暂停后台修改，重新校验包及目标条件，然后备份目标原数据。

同一账号下相同 userID／AgentID 合并归属；新增记录插入，同标识同内容跳过，同标识不同内容调用现有记忆冲突逻辑。没有适用策略的冲突明确报告，不静默覆盖。保留目标已有附件，合并前验证最终引用。

按合并结果恢复内容并重建受影响索引，校验业务内容、引用和检索后开放目标。失败时保持维护，清理本次修改范围并恢复备份，恢复校验成功后才开放。持久任务状态支持进程重启后识别未完成恢复。

目标恢复备份与迁移包不同：备份包含恢复原实例所需的业务内容、附件、索引及受影响运行状态。恢复失败时保持隔离并报告原因。

## 组件职责

| 组件 | 职责 |
|---|---|
| #413 协调基础 | 源端内容持久化屏障及期限；目标完整维护、进程协调和生命周期，不读取迁移数据 |
| #414 备份恢复 | 内容、附件和索引备份、完整性校验及恢复组件，以及恢复所需的流式写入、索引遍历和资源身份接口 |
| #395 核心迁移 | 同源快照导出、SQL 快照读取、记录与附件副本固定、迁移预检、合并、索引重建、失败恢复及统一 API／CLI 任务 |
| #409 后端扩展 | 同内容存储类型下的数据库和向量后端变化 |
| #410 内容转换 | AGFS↔SQL 规范化与恢复差异 |
| #412 GUI | 使用统一 API，展示快照、打包、备份、合并、重建、校验与恢复进度 |
| #415 共享空间 | 满足条件时整个共享空间迁入空目标，否则明确跳过 |

AGFS 使用受内容写屏障保护的副本读取。SQL 可采用单事务一致性读取；文件附件仍需固定字节。源端快照和目标维护分别控制，不建立第二套 GUI／CLI 执行逻辑，不增加变更追踪或增量补齐。

## 验收

验证真实内容写入与快照并发、完整修改边界、多进程隔离、读取和模型计算继续、索引写入不阻塞快照、超时恢复及快照后的变化不进入包。目标验证非空合并、冲突处理、附件保留、重建检索、失败与重启恢复，以及维护期间的业务隔离。结果绑定代码版本和实际后端范围。
