# 记忆导入导出设计

版本：v0.7。关联需求：[Issue #90](https://gitcode.com/opengauss/oGMemory/issues/90)。

## 1. 目标与边界

实现持久化记忆的跨机器迁移：**源端固定快照 → 统一迁移包 → 目标维护与完整备份 → 合并与索引 → 校验后开放业务**。

- 源端建立快照期间暂停写入、读取继续；数据和附件固定后恢复写入，再压缩。快照之后的源端变化不补齐。
- 目标可为空或非空，导入及恢复期间禁止业务读写，管理接口可用；先排空请求与后台修改，再验证完整备份。
- 仅 ROOT 操作全部账号。保留用户、Agent 及所属范围，不迁移凭证、实例角色和连接配置。
- HTTP、MCP、独立索引及其他同机业务进程共用持久化协调工作区。未接入协调的跨主机进程或直接存储访问必须停止。
- 不建设增量同步、影子版本切换或通用快照系统。

## 2. 数据范围

| 数据 | 处理方式 |
|---|---|
| 记忆节点 | 保留正文、摘要、概览、类型、业务元数据、状态、版本、时间和所属范围，包含已归档节点 |
| 关系与历史归档 | 保留关系两端、类型、权重、原因，以及已落盘消息和来源引用 |
| 依赖的技能、资源与本地附件 | 保存支持类型的内容及引用；声明的附件随包保存并在目标目录恢复路径 |
| 检索索引 | 不导出物理索引，使用目标配置重建 |
| 共享空间 | 符合条件时整批迁移空间、成员、来源授权、规则、共享内容、证据和访问名单 |
| 运行状态 | 排除会话窗口、队列、锁、重试状态、旧请求回执及工作区同步注册 |
| 环境与管理配置 | 不迁移凭证、连接信息和主机配置 |

运行状态必须按明确的存储位置或字段识别，不能按目录名称跳过同名业务节点，也不能整体丢弃 metadata。写入回执包括 `memories/.write_operations/` 定位节点及对应回执字段。

场景状态、异构图、技能候选及外部 trace/tool 证据依赖（包括 `ctx://{account}/traces/...`）不在支持范围内。存在未适配的业务数据、必要依赖或未完成的业务操作时明确拒绝，不静默丢弃或自动转换。

附件只读取操作员指定目录内的普通文件，按内容摘要去重保存。恢复时更新声明的附件路径，不替换正文中的历史路径、不复制任意工作区、不执行附件内容。

共享空间仅迁入同内容后端、同 SQL 数据库类型且结构兼容的空业务目标；所需有效身份及来源授权资格必须已存在。否则整批跳过共享空间及其专属内容、附件和索引，继续处理普通记忆；普通记忆因此缺失必要证据时拒绝导入。身份初始化不影响空业务目标判断。规则迁入后暂停，不迁移源任务或租约，不合并已有空间。预检报告数量及跳过原因，进入维护后重新检查，选择变化须重新确认。

## 3. 迁移包契约

使用单个 gzip／USTAR 包；普通包为版本 1，共享空间包为版本 2。成员属主统一为 UID/GID 0、空属主名称，单成员不超过 8 GiB−1 字节：

| 成员 | 内容 |
|---|---|
| `manifest.json` | 格式版本、软件版本、来源描述、文件集合、记录数量、大小及校验值 |
| `entities/*.jsonl` | 规范化的节点、关系、历史归档 |
| `blobs/sha256/*` | 以内容摘要命名的附件字节 |

包只保存逻辑数据，不包含数据库私有格式或旧向量。统一规范化时间戳和关系数值，对账比较业务记录，不比较数据库内部表示。

版本 2 将共享目录与内容分别保存为 `spaces.jsonl`、`space_nodes.jsonl`，清单记录共享 SQL 类型和结构摘要。普通与共享内容在完整快照上统一校验引用。

来源描述仅包含下列非敏感字段，不包含密码、API Key、服务地址或连接串：

| 分类 | 字段 |
|---|---|
| Embedding | `provider`、`model`、`dimension`、`model_version` |
| 内容存储 | `backend`、`database_type`、`database_version` |
| 向量存储 | `backend` |

SentenceTransformer 维度从模型读取，其他提供方记录配置指定的输出维度；SQL 类型与版本来自实际连接。无法可靠获取的模型维度或版本记为 `null`，不作推断。缺少来源描述的旧包可进行格式校验，但不能导入；须在源端重新导出。

输入检查覆盖读取、解压、解析和业务校验。压缩输入、解压总量、成员数量、清单及单条 JSONL 分别受限；只接受 USTAR 普通文件，PAX、GNU 长名称和稀疏文件扩展在载荷解析前拒绝。tar 结束后检查预读缓冲和剩余流，仅接受完整结束标记及块对齐的零填充，并核验 gzip 校验值与完整性；拒绝拼接成员和非零尾随数据。通过全部检查后才允许恢复业务数据。

## 4. 导出与导入流程

**导出**：暂停新写入并排空在途写入 → 固定规范化数据和附件 → 恢复写入 → 写包校验 → 提供下载。目录扫描和附件分块处理共用快照期限，HTTP 读取超时受剩余预算限制；超过预算则退出并恢复写入。导出进程中断后，任务状态检查在取得执行锁、确认未修改业务数据后释放停写限制，保留未完成写入记录。

**预检**：校验迁移包、引用和附件 → 检查目标可表示性、模型及索引约束 → 展示新增、重复、冲突数量和环境差异。结果仅供确认，导入前重新检查。

**导入**：维护门禁禁止业务读写 → 排空并落盘 → 验证完整备份 → 合并并构建索引 → 回读对账 → 持久化结果 → 刷新各进程缓存 → 开放业务。

同账号相同用户／Agent 归属直接复用；新记录插入，规范化内容相同则跳过。记忆内容冲突复用现有分类策略，必要时调用目标模型；不重新抽取全部节点。无法处理的资源、归档或关系冲突拒绝导入。标识改变时调整导入记录的关系和证据引用，受影响的目录重新生成汇总。

应用账本记录来源内容摘要及目标映射，重复包不重复累加。来源环境用于同源准入检查及差异提示，不覆盖目标配置。所有已知约束在业务修改前验证，冲突策略生成的结果再次校验。

## 5. 组件与索引契约

| 组件 | 职责 |
|---|---|
| 迁移服务 | 编排预检、恢复、重建和校验；使用磁盘临时清单检查身份、引用并计算摘要 |
| 内容存储适配器 | 按源或目标配置选择 AGFS／SQL，负责布局、类型转换、迁移条件和记录读写 |
| 迁移包组件 | 流式读写逻辑记录与附件，执行格式、完整性及资源限制检查 |
| 索引重建组件 | 复用正常索引记录构建、embedding 和写入能力，重建目标启用的检索投影 |
| 管理 API 与 CLI | 上传下载、创建任务、预检确认、进度查询与结果展示 |

仅支持同源迁移：内容存储类型、SQL 数据库类型和向量后端必须一致，允许模型和向量维度变化。AGFS→AGFS、SQL→SQL 共用迁移协议；源目标使用各自连接配置。

目标采用 `retrieval.mode=agfs` 时，不初始化 Embedding 或向量库，不备份或重建向量；导入与恢复后丢弃进程内 FTS 缓存，由正常检索按目标设置重建。来源清单以 `none` 描述未启用的模型和向量后端。源目标须使用相同的向量后端；无 Embedding 模式之间迁移不创建向量。

默认检索模式下，新增或改变的内容使用目标模型构建向量，不复用来源向量，检索排序可能变化。未改变的目标向量保留实际值，导入前核对其模型身份和维度。目标启用的词法索引及关系投影一并重建，归档或禁止索引的数据不进入活跃检索。AGFS 按实际存储路径核对关系源节点，允许目录 URI 的尾斜杠差异。SQL 目标要求关系端点与存储 URI 精确一致；启用 SQL 关系投影时，两端还必须属于节点记录，历史归档端点在预检及写入前拒绝。历史归档的 provenance 引用不受此限制。

向量后端的 `get_record(id)` 返回一致的 `IndexRecord`：完整 `text`、原有 `filters`（账号、owner、类别、内容类型及存在时的资源类型、共享空间、授权资源、内容版本和状态）和约定的业务 `metadata`。重建与 Outbox 共用 embedding 元数据增强逻辑，保留可用的目标模型标识和实际向量维度。共享内容在目标索引回读校验成功后标记就绪，不沿用源投影就绪状态。

向量适配器检查持久化能力、已有表／collection 约束和记录载荷；空索引不能绕过维度检查。Milvus 的 `validate_records()` 复用写入编码逻辑，在预检和恢复前检查文本、字段及包含目标模型身份的元数据载荷限制。未实现迁移能力的后端明确拒绝，不新增插件注册或能力协商框架。

## 6. 管理与失败处理

客户端使用 ROOT 身份调用迁移 API，上传、下载、预检、任务及恢复接口均鉴权。后台任务不依赖客户端连接存活；持久化请求标识绑定操作和迁移包，响应丢失后按原任务查询或重试。

工作区保存跨进程门禁、参与进程状态、任务和应用账本，并以系统文件锁串行执行迁移。导入前的内部备份覆盖目标业务、必要运行状态、声明附件及实际向量，绑定目标资源身份并校验完整性；它与不含运行状态的跨机器迁移包用途不同。

修改后失败，先确认写入已结束，再清理本实例备份范围并恢复各存储，回读校验成功后刷新业务缓存、解除维护。无法确认远端操作完成、备份损坏或恢复校验失败时保持维护。成功结果已持久化但响应丢失时只完成状态恢复，不重复合并或回滚成功数据。

导入导出统一使用正常服务的 `/api/v1/migration` 接口和持久化任务队列。CLI 使用该接口；CLI 仅处理参数、文件传输、进度和退出码，不创建独立迁移服务或执行链。

## 7. 验收与操作说明

验收检查迁移前后的数据与权限一致性、索引重建和业务读取，以及异常输入在目标写入前被拒绝。向量后端使用统一契约测试，并检查跨后端迁移和新进程读取。

启动命令、配置要求及资源限额见[操作说明](/docs/deployment/memory-migration.md)。
