# 记忆导入导出设计

版本：v0.3。关联需求：[Issue #90](https://gitcode.com/opengauss/oGMemory/issues/90)。

## 1. 目标与边界

实现已持久化记忆的跨机器迁移，自动适配 AGFS／SQL 内容存储，并提供 GUI 导入导出入口。统一流程为：**导出逻辑数据 → 传输迁移包 → 恢复到空目标 → 重建索引 → 校验**。

- 在维护窗口内运行单个迁移管理进程；源端完成在途操作及落盘，源、目标均停止业务写入和后台修改。迁移模式不启动业务 worker，不提供业务写入接口。
- 按实例全量迁移，保留账号、用户、Agent 标识和所属范围；目标业务存储及相关索引必须为空。
- 来源描述不覆盖目标配置。身份凭证、数据库连接及客户端切换沿用现有管理方式。
- 不实现在线增量、合并覆盖、断点续跑、账号映射、工作区重绑定或分布式停写协调。失败不自动删除目标数据，部分恢复的数据不能用于业务服务。

## 2. 数据范围

| 数据 | 处理方式 |
|---|---|
| 记忆节点 | 保留正文、摘要、概览、类型、业务元数据、状态、版本、时间和所属范围，包含已归档节点 |
| 关系与历史归档 | 保留关系两端、类型、权重、原因，以及已落盘消息和来源引用 |
| 依赖的技能、资源与本地附件 | 保存支持类型的内容及引用；声明的附件随包保存并在目标目录恢复路径 |
| 检索索引 | 不导出物理索引，使用目标配置重建 |
| 运行状态 | 排除会话窗口、队列、锁、重试状态、旧请求回执及工作区同步注册 |
| 环境与管理配置 | 不迁移凭证、连接信息和主机配置 |

运行状态必须按明确的存储位置或字段识别，不能按目录名称跳过同名业务节点，也不能整体丢弃 metadata。写入回执包括 `memories/.write_operations/` 定位节点及对应回执字段。

场景状态、异构图、技能候选及外部 trace/tool 证据依赖（包括 `ctx://{account}/traces/...`）不在支持范围内。存在未适配的业务数据、必要依赖或未完成的业务操作时明确拒绝，不静默丢弃或自动转换。

附件只读取操作员指定目录内的普通文件，按内容摘要去重保存。恢复时更新声明的附件路径，不替换正文中的历史路径、不复制任意工作区、不执行附件内容。

## 3. 迁移包契约

使用单个 gzip／USTAR 包，格式版本为 1：

| 成员 | 内容 |
|---|---|
| `manifest.json` | 格式版本、软件版本、来源描述、文件集合、记录数量、大小及校验值 |
| `entities/*.jsonl` | 规范化的节点、关系、历史归档 |
| `blobs/sha256/*` | 以内容摘要命名的附件字节 |

包只保存逻辑数据，不包含数据库私有格式或旧向量。统一规范化时间戳和关系数值，对账比较业务记录，不比较数据库内部表示。

来源描述仅包含下列非敏感字段，不包含密码、API Key、服务地址或连接串：

| 分类 | 字段 |
|---|---|
| Embedding | `provider`、`model`、`dimension`、`model_version` |
| 内容存储 | `backend`、`database_type`、`database_version` |
| 向量存储 | `backend` |

SentenceTransformer 维度从模型读取，其他提供方记录配置指定的输出维度；SQL 类型与版本来自实际连接。无法可靠获取的模型维度或版本记为 `null`，不作推断。缺少来源描述的旧包仍可校验，但不能比较来源环境。

输入检查覆盖读取、解压、解析和业务校验。压缩输入、解压总量、成员数量、清单及单条 JSONL 分别受限；只接受 USTAR 普通文件，PAX、GNU 长名称和稀疏文件扩展在载荷解析前拒绝。tar 结束后检查预读缓冲和剩余流，仅接受完整结束标记及块对齐的零填充，并核验 gzip 校验值与完整性；拒绝拼接成员和非零尾随数据。通过全部检查后才允许恢复业务数据。

## 4. 导出与导入流程

**导出**：检查源端迁移条件 → 读取并规范化数据和附件 → 检查身份、必要引用及支持范围 → 写包并验证完整性 → 发布下载文件。

**预检**：校验迁移包及业务记录 → 检查附件恢复条件 → 检查目标存储和索引为空 → 检查模型与索引约束 → 展示源端与目标端差异。

**导入**：重新校验当前包与目标条件 → 探测目标模型 → 恢复节点、归档、附件和关系 → 重建索引 → 回读对账并验证索引 → 输出结果。

GUI 预检结果只用于展示和操作确认，不替代导入时的检查。同一次导入保留一份已校验的临时包和清单，恢复及最终对账共同使用；不重复解包，不跨任务缓存校验结论。已知模型维度不匹配时在创建索引前拒绝，维度未知时明确提示，并在写入前通过模型探测验证。

## 5. 组件与索引契约

| 组件 | 职责 |
|---|---|
| 迁移服务 | 编排预检、恢复、重建和校验；使用磁盘临时清单检查身份、引用并计算摘要 |
| 内容存储适配器 | 按源或目标配置选择 AGFS／SQL，负责布局、类型转换、迁移条件和记录读写 |
| 迁移包组件 | 流式读写逻辑记录与附件，执行格式、完整性及资源限制检查 |
| 索引重建组件 | 复用正常索引记录构建、embedding 和写入能力，重建目标启用的检索投影 |
| 管理页面与 API | 上传下载、创建任务、预检确认、进度查询与结果展示 |

AGFS→AGFS、AGFS→SQL、SQL→AGFS、SQL→SQL 共用迁移协议。内容存储和向量后端分别配置。

无论源、目标模型是否相同，均使用目标模型重建向量，检索排序可能变化。保留已有正文和摘要，不重新抽取或调用 LLM 改写。目标启用的词法索引及关系投影一并重建，归档或禁止索引的数据不进入活跃检索。AGFS 按实际存储路径核对关系源节点，允许目录 URI 的尾斜杠差异。SQL 目标要求关系端点与存储 URI 精确一致；启用 SQL 关系投影时，两端还必须属于节点记录，历史归档端点在预检及写入前拒绝。历史归档的 provenance 引用不受此限制。

向量后端的 `get_record(id)` 返回一致的 `IndexRecord`：完整 `text`、原有 `filters`（账号、owner、类别、内容类型及存在时的资源类型）和约定的业务 `metadata`。重建与 Outbox 共用 embedding 元数据增强逻辑，保留可用的目标模型标识和实际向量维度。

`check_migration_target()` 由向量适配器检查持久化支持、空状态及已有表／collection 约束；记录为空不能绕过维度检查。未实现迁移能力的后端明确拒绝，不新增插件注册或能力协商框架。

## 6. 管理与失败处理

普通 Memory Viewer 提供入口，实际操作在独立迁移模式中执行。使用迁移管理员密钥认证，账户 Admin Key 不能替代；下载通过会话 cookie 授权，不在链接中传递密钥。

工作区使用 Windows／POSIX 非阻塞文件锁，单进程内一次执行一个任务。任务状态采用 UTF-8 JSON，读写互斥。页面关闭不取消任务，刷新可查询；进程重启将中断任务标记失败，不自动续跑。

上传下载采用流式处理；任务提交 JSON 在解析前执行独立限额。失败报告不能标为成功，部分导入目标由运维确认隔离范围后清理。验证成功后，目标业务服务须使用相同的索引配置并能够访问恢复后的附件目录。

## 7. 验收与操作说明

验收检查迁移前后的数据与权限一致性、索引重建和业务读取，以及异常输入在目标写入前被拒绝。向量后端使用统一契约测试，并检查跨后端迁移和新进程读取。

启动命令、GUI 步骤、配置要求及资源限额见[操作说明](/docs/deployment/memory-migration.md)。
