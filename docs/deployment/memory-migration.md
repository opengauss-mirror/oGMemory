# 记忆导入导出操作说明

通过统一迁移包在不同机器间迁移已持久化记忆，支持 AGFS／SQL 四种存储转换。目标按自身配置恢复数据，重新生成向量及已启用的词法、关系索引。数据范围与协议见[设计说明](/docs/architecture/memory-migration.md)。

## 准备

1. 源端完成在途写入、归档及落盘，停止源、目标业务 HTTP、MCP 和独立后台任务。
2. 准备空目标业务存储和持久化向量库，配置目标模型。已有表或 collection 的维度须与模型一致；`memory` 向量后端不能作为导入目标。
3. 配置目标身份和访问权限。迁移保留账号、用户和 Agent 标识，不复制凭证或连接配置。
4. SQL 全实例迁移使用可绕过租户 RLS 的管理员：PostgreSQL superuser 或 openGauss SYSADMIN。openGauss 数据库使用 `DBCOMPATIBILITY 'PG'`。

迁移期间保持停写，源端直到客户端切换完成后再恢复使用。

## 启动迁移页面

在源、目标机器分别使用各自的配置启动：

```bash
ogmem migration \
  --config /path/ogmem.yaml \
  --workspace /path/migration-work \
  --maintenance-confirmed
```

默认地址为 `http://127.0.0.1:8091`，远端可通过 SSH 转发访问。使用配置中的 `auth.root_api_key` 或环境变量 `OGMEM_MIGRATION_API_KEY` 登录，账户 Admin Key 不能替代。

普通 Memory Viewer 的“导入导出”入口提供启动说明。迁移模式只开放管理页面和迁移接口；`--maintenance-confirmed` 表示已完成停写准备，不会自动停止其他进程。

## 导出与导入

1. 源页面点击“开始导出”，完成后下载 `.ogmem.tar.gz` 包。
2. 目标页面选择文件，点击“上传并预检”，查看源端与目标端的模型、维度、内容存储和向量后端差异；按提示处理配置或数据问题。
3. 点击“开始导入”。服务器重新检查迁移包、空目标和模型配置，恢复数据并重建索引。来源描述不覆盖目标配置，更换模型可能改变检索排序。
4. 校验成功后停止迁移进程，启动目标业务服务，确认读取、检索及附件访问正常，再切换客户端。业务服务使用与迁移时相同的目标索引配置。

页面关闭不取消任务，刷新后可查看进度。任务失败时，可按任务 ID 在服务端日志中查看脱敏原因、执行阶段和调用栈。中断任务标记失败，不自动续跑；若目标已有部分写入，由运维确认隔离范围并清理后重试。源端恢复写入后需要重新导出再迁移。

## 本地附件

节点的 `source_path`、`blob_path`、`media_path`、`image_path`、`video_path`、`audio_path` 可声明本地附件。源、目标启动命令分别追加：

```bash
--asset-root /path/persistent-assets
```

源端只读取该目录内的普通文件，相对路径以此目录解析。附件按内容摘要去重，目标恢复字节并更新声明的路径；正文中的历史路径保持原样。目标目录应持久化，并可由正常业务服务访问，包括所需的容器挂载。

## 使用限制

- 迁移到空目标，不合并或覆盖已有数据；运行中会话、队列、锁、旧请求回执及工作区同步状态不随包恢复。
- 场景状态、异构图、技能候选及外部 trace/tool 证据依赖会被拒绝。SQL 目标要求关系端点与节点或归档 URI 完全一致，包含尾部斜杠；启用 SQL 图索引时，端点还必须是节点记录。记忆的 provenance 归档引用不受此限制。
- 仅接受本工具生成的 gzip／USTAR 迁移包。损坏包、不支持的扩展头、缺失依赖和非空目标均报错。
- 默认上传和解压数据上限为 10 GiB，单个附件或 JSONL 数据集上限为 8 GiB−1 字节，单条 JSONL 记录上限为 16 MiB。可用 `--max-upload-mib` 下调上传上限；预留迁移包、解压数据、清单和附件所需磁盘空间。
